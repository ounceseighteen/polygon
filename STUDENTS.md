## Что вам дают

Папка `teams/teamXX/legacy_app` со «старым» приложением
на Flask + Python + SQLite. Оно работает, но медленное,
с багами и плохой архитектурой.

## Ваша задача

Улучшить его по метрикам, не сломав функциональность.


## Что можно

- любой рефакторинг внутри Flask + Python + SQLite;
- индексы, WAL, пагинация, кэш в памяти;
- разбиение `app.py` на модули и blueprints;
- свои тесты (pytest), свой `config.py`, нормальное `logging`.

## По каким метрикам оценивают

- **Скорость ответа** — p95 на `/api/items` и `/api/report`.
- **Покрытие тестами** — через `pytest --cov`.
- **Качество кода** — `ruff`, `radon` (цикломатическая сложность), дублирование.
- **Надёжность** — число `ERROR` в `app.log` на 1000 запросов.
- **Безопасность** — `bandit`, отсутствие f-string SQL.
- **Читаемость** — `README.md`, `config.py`, наличие папки `tests/`.

## Оценка

Автоматическая, от **2** до **5**.

Сначала gate — проверка API (acceptance). Не прошёл → **2**.

Если прошёл, считается score:

```
0.30·скорость + 0.20·тесты + 0.20·качество
+ 0.15·надёжность + 0.10·безопасность + 0.05·документация
```

Перевод в оценку:

| Score | Оценка |
|---|---|
| ≥ 0.85 | 5 |
| 0.70–0.84 | 4 |
| 0.50–0.69 | 3 |
| < 0.50 | 2 |

Предохранители (понижают оценку):

- Сломанный API → **2**.
- Подмена `tools/*` → **2**.
- Нет ни одного теста → максимум **3**.
- `coverage < 30%` при высоком score → максимум **3**.
- Остались `except: pass` → максимум **4**.
- Скорость почти не улучшена → максимум **3**.

## Советы

1. **Начните с индексов и N+1** — самый быстрый прирост скорости.
   - `CREATE INDEX idx_orders_item_id ON orders(item_id);`
   - `CREATE INDEX idx_orders_created_at ON orders(created_at);`
2. **Включите WAL для SQLite** — уменьшит блокировки при записи:
   ```python
   conn.execute("PRAGMA journal_mode=WAL")
   ```
3. **Замените f-string SQL на параметризованные запросы** — убирает инъекции и ускоряет за счёт кэша запросов:
   ```python
   cur.execute("INSERT INTO orders (item_id, qty) VALUES (?, ?)", (item_id, qty))
   ```
4. **Добавьте `logging` вместо `print`** и уберите `except: pass`:
   ```python
   import logging
   logging.basicConfig(filename="app.log", level=logging.INFO)
   ```
5. **Напишите 5–10 тестов** на ключевые сценарии:
   - список товаров возвращает 200 и список;
   - создание заказа возвращает 201;
   - отчёт возвращает `total` и `by_item`;
   - некорректный ввод возвращает 400, а не 500.
6. **Разбейте `app.py` на модули** — вынесите БД в `db.py`, роуты в `routes.py`, конфиг в `config.py`. Это влияет на читаемость и на `docs`-метрику.
7. **Не гонитесь за одной метрикой** — провал в другой обнулит предохранителем. Улучшайте постепенно: скорость → тесты → качество.

## Частые ловушки

| Проблема | Что делать |
|---|---|
| `database is locked` при нагрузке | Включить WAL: `PRAGMA journal_mode=WAL` |
| `pytest` не находит тесты | Создать папку `tests/`, файлы `test_*.py` |
| `ruff` ругается на всё | Начать с `ruff check . --fix`, потом вручную |
| Отчёт медленный | Добавить индекс на `orders.created_at` |
| `api/items` медленный | Убрать N+1: один `LEFT JOIN` вместо цикла |
